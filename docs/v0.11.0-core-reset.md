# v0.11.0 Core Reset

## Зачем

DLS накопил recovery-контракты быстрее, чем продуктовую ценность. Один delivery
cycle мог проходить через несколько status-команд, operation IDs, pack recovery,
telemetry adapters и legacy branches. Core Reset сохраняет proof, но удаляет
процесс ради процесса.

## Сохраняемые инварианты

1. Отдельные human approvals для definition, architecture и design.
2. Exact-HEAD validation evidence.
3. Независимый read-only review и reviewer-owned verification.
4. Раздельные review-clear, accepted, release и production.
5. One-writer per change, atomic state, flock и single-flight model calls.

## Удалённые контракты

- 18 отдельных status/recovery/evidence/cache/review primitives;
- executable ReviewPack/ReviewIR v1/v2;
- operation/candidate/recovery history;
- controller rollout parser и task-reuse telemetry;
- final-full и отдельные specialist lanes;
- plaintext/native-prose recovery;
- generic dependency stages, overlap scan и delivery-map;
- recursive profiles, worktree transfer journals и path registry;
- schemas без runtime consumer и KANO runtime validation.

## Migration

```text
dls upgrade --dry-run
dls upgrade --apply
```

Dry-run проверяет все references. Apply сохраняет ignored backup в
`.dls/archive/pre-0.11/`, переносит только current truth и не меняет product
source или Git history. Mixed migration блокирует обычный runtime до повторного
идемпотентного `upgrade --apply`.

`v0.11.1` безопасно переводит legacy definition digests на новый контракт,
только когда authored artifacts в подтверждённой Git-ревизии совпадают с
текущими. Реальное изменение definition остаётся stale и требует нового review.
Повторный `upgrade --apply` исправляет state, уже созданный `v0.11.0`.

## Exit criteria

- routine/standard code review: один analysis call;
- critical: один или два reviewers только по fixed risk triggers;
- reconciliation только при прямом structured conflict;
- repair без source и без повторного analysis;
- 12 публичных команд;
- real `swift-of-mcp` dry-run: 19 changes и 59 accepted-in-base dependencies;
- no product-source mutation during migration/review pilots;
- LOC reduction reported, but not used as a standalone release gate.
