# Easy Peasy DLS v0.9.1 — bounded final review и zero-call recovery

## Подтверждённая причина

В remediation-review `17557348-55db-56a8-8252-a256bf89251b`
финальный whole-change pass был выбран корректно: targeted semantic и
reconciliation завершились без actionable findings, поэтому review-clear
требовал final-full.

Сбой вызван budget contract v1:

- Codex CLI сообщает token usage только в завершающем `turn.completed`, поэтому
  token limit проверяется после model call;
- static context estimate не учитывает повторное включение tool output в
  model context;
- перед final-full DLS не резервирует остаток aggregate budget;
- final-full получил полный checkout и выполнил 48 команд, хотя его начальный
  DLS context занимал только 163 050 bytes.

Фактический расход final-full — 6 364 076 processed tokens при lane target
6 000 000. Измеренный child aggregate — 8 718 502 при target 8 000 000.
При этом exact-HEAD model output существует, завершился с exit code 0 и проходит
строгую ReviewDecision-валидацию. Он пока не является каноническим verdict,
поскольку ReviewIR не импортирован.

## Реализация

1. Ввести `dls-review-budget/v2`: target budget отделяется от ограниченного
   recovery ceiling. Timeout, command events, transcript и output bytes
   остаются реально исполняемыми hard limits.
2. Разрешить zero-call recovery уже завершённого структурно валидного решения,
   если token overrun не превышает 10% target и одновременно абсолютный ceiling
   600k на critical lane / 800k на critical aggregate.
3. Перед final-full строить deterministic budget plan и не запускать прежний
   unrestricted whole-checkout pass.
4. Выполнять final-full в input-only workspace с exact epic patch, changed-path
   coverage manifest, canonical definition, prior decisions и evidence metadata.
5. Ограничить final-full 16 command events, 15 минутами и transcript 1 MiB.
   Bundle больше 2 MiB блокировать до model call без silent truncation.
6. Добавить DLS-owned provenance target/ceiling/overrun/recovery в lane state,
   ReviewIR и metrics. Raw output и transcript остаются immutable.
7. `review-status` возвращает `resume-review-budget`, только когда recovery
   доказуемо безопасен. Integrity drift, invalid output и превышение ceiling
   остаются terminal `inspect-review-budget`/`inspect-review-integrity`.
8. Защитить deterministic ReviewIR assembly/import отдельным change-scoped
   finalization single-flight, чтобы два controller-вызова не импортировали
   разные transient provenance snapshots после одних и тех же completed lanes.

## Проверка и выпуск

- Сохранить state schema v1 и ReviewPack/ReviewIR v2.
- Добавить sanitized fixture реального EPIC-01 budget failure.
- Доказать zero-call recovery, неизменность attempts/usage/raw digests и
  отсутствие product-source mutations.
- Проверить constrained final-full, coverage completeness, >2 MiB preflight,
  stage hard limits, concurrent finalization и legacy artifacts.
- Пройти полный suite, validators, Python 3.11/3.13 и disposable install.
- Локальным release commit восстановить реальный review с тем же operation ID.
- Публиковать `v0.9.1` только после появления canonical `review_result_path`,
  verdict, presentation и Delivery Receipt без новых model calls.

## Зафиксированные решения

- final-full остаётся обязательным для clean remediation;
- default token targets не повышаются;
- уже потраченный валидный result не выбрасывается;
- будущий final-full становится input-only и stage-bounded;
- пользователь не получает новых ручных команд;
- EPIC-01 product source не изменяется.
